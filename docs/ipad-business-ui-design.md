# iPad向け業務アプリ UI設計

## 1. 設計方針

- **iPad最優先**: 11〜13インチのランドスケープ利用を基準に、片手保持・卓上利用の両方を想定する。
- **1画面1目的**: 一覧、詳細、入力、進行管理の4種類を基本にし、各画面でユーザーの主目的を明確に分離する。
- **高情報密度 + 低認知負荷**: 情報は多く載せるが、視線の流れとアクション配置を固定して迷いを防ぐ。
- **現場担当者と管理者の共用**: 権限や役割で見せる情報量・操作範囲は変えるが、画面構造は共通化する。
- **下部固定アクション**: 主要操作は下部の固定アクションバーに集約し、移動量を減らす。
- **誤操作防止**: 破壊的操作は色・距離・確認導線で区別し、操作対象も明示する。
- **実務優先のデザイン**: カード、表、フォームを基本に、装飾を抑えた信頼感あるUIにする。
- **Material Design 3に近い整理感**: 余白、階層、トーン、コンポーネント一貫性で整理感を出す。

---

## 2. 想定利用者と利用シーン

### 現場担当者
- 当日対応案件の確認
- 作業開始・終了の記録
- 現場情報の入力、写真添付、コメント登録
- ステータス更新やチェック項目の処理

### 管理者
- 複数案件の進行状況確認
- 担当者別・拠点別の一覧監視
- 詳細確認、差し戻し、承認
- 進行遅延やエラー案件の優先処理

### 共通要件
- 手袋や急いだ操作でも誤タップしにくい
- 画面遷移が少なく、現在地が分かりやすい
- 状況の見落としを防ぐため、重要情報は色だけでなくラベルでも表現する

---

## 3. 画面一覧

### 基本4画面
1. **案件一覧画面**
   - 案件・作業・申請などを一覧で確認する画面
   - 絞り込み、並び替え、優先度確認、担当確認が主目的

2. **案件詳細画面**
   - 1案件の詳細情報、履歴、関連情報、ステータスを確認する画面
   - 現場担当者は内容確認、管理者は判断・承認が主目的

3. **入力画面**
   - 点検結果、申請内容、作業記録などを登録・編集する画面
   - フォームの正確な入力と保存が主目的

4. **進行管理画面**
   - 複数案件や工程の進捗を横断管理する画面
   - 管理者中心だが、現場担当者も自分の進行確認に使用可能

### 補助画面
5. **ダッシュボード画面**
   - ログイン直後の役割別サマリー
   - 今日の件数、遅延、未処理、重要通知を表示

6. **検索・絞り込みパネル**
   - 一覧や進行管理から開くサイドパネル
   - 詳細条件で対象を絞る

7. **承認・確認ダイアログ**
   - 承認、差し戻し、削除、完了など重要操作前の確認

8. **通知・履歴画面**
   - 更新履歴、差し戻し理由、システム通知を時系列で確認

---

## 4. 各画面のワイヤー説明

## 4-1. ダッシュボード画面

### 目的
- ユーザーが次に取るべき行動をすぐ判断できるようにする。

### レイアウト
- **上部ヘッダー**
  - 左: 画面タイトル「ダッシュボード」
  - 中央: 日付、拠点切替、ロール表示
  - 右: 通知、検索、ユーザーメニュー
- **メインエリア**
  - 上段: KPIカード（本日の対応件数、未完了、承認待ち、遅延）
  - 中段左: 自分の担当一覧カード
  - 中段右: 注意案件カード
  - 下段: 最近更新された案件の表
- **下部固定アクションバー**
  - 「一覧へ」「新規入力」「進行確認」「通知」

### ワイヤーイメージ
- KPIは4〜6枚のカードを横並び
- 下段は表形式で密度高めに表示
- 危険案件は強い色ではなく、バッジとアイコンで強調

---

## 4-2. 案件一覧画面

### 目的
- 多数案件から対象を素早く見つけ、優先順位を判断する。

### レイアウト
- **上部ヘッダー**
  - 左: タイトル「案件一覧」
  - 中央: タブ（全件 / 自分担当 / 要確認 / 完了）
  - 右: 検索、絞り込み、表示切替
- **左サブエリア（任意表示）**
  - 絞り込みパネル
  - 拠点、担当者、状態、日付、優先度
- **中央メインエリア**
  - 上: サマリー行（総件数、表示件数、選択条件）
  - 中: 表 + カードのハイブリッド一覧
- **下部固定アクションバー**
  - 「詳細を見る」「ステータス更新」「一括処理」「新規作成」

### 一覧構成
- 1行に以下を表示
  - 案件ID
  - 顧客名 / 現場名
  - 作業種別
  - 予定日時
  - 担当者
  - 現在ステータス
  - 優先度
  - 最終更新
- 重要案件は左端に縦アクセントバー
- 行選択時は背景トーンとチェックで視認性を確保

### ワイヤーイメージ
- 標準は**表表示**
- 切替で**カード表示**も利用可能
- 1件をタップで詳細へ、長押し不要
- 一括処理は複数選択モードでのみ表示を強める

---

## 4-3. 案件詳細画面

### 目的
- 案件の全体像を把握し、必要な判断や次アクションを実行する。

### レイアウト
- **上部ヘッダー**
  - 左: 戻る、案件ID、ステータスチップ
  - 中央: 案件名 / 現場名
  - 右: 共有、履歴、メニュー
- **メイン2カラム**
  - 左カラム（主情報 65%）
    - 基本情報カード
    - 作業内容カード
    - 添付・写真カード
    - コメント / 履歴カード
  - 右カラム（補助情報 35%）
    - 進行ステップカード
    - 担当情報カード
    - 承認状況カード
    - 注意事項カード
- **下部固定アクションバー**
  - 現場担当者: 「開始」「完了」「報告入力」
  - 管理者: 「承認」「差し戻し」「担当変更」

### ワイヤーイメージ
- 画面上部でステータスが常に分かる
- 左側で内容確認、右側で判断材料確認
- 重要操作は下部固定、補助操作は右上メニューへ格納

---

## 4-4. 入力画面

### 目的
- 必要な入力を正確・短時間で完了させる。

### レイアウト
- **上部ヘッダー**
  - 左: 戻る
  - 中央: タイトル「作業報告入力」など
  - 右: 一時保存状態、入力ヘルプ
- **メインエリア**
  - セクション分割フォーム
    1. 基本項目
    2. 実施内容
    3. 数値・チェック
    4. 添付資料
    5. 備考
- **右サイド補助列（任意）**
  - 必須項目進捗
  - 入力エラー一覧
  - 参照情報
- **下部固定アクションバー**
  - 「一時保存」「下書き破棄」「確認へ」「送信」

### フォーム設計ルール
- 1セクション内は2列まで
- タップ対象は44pt以上
- 数値入力はテンキー優先
- スイッチは業務的に誤解が少ない箇所のみ使用
- 確認が必要な値変更時はインライン警告を表示

### ワイヤーイメージ
- 長大フォームでも、セクションをカード化して見通しを保つ
- エラーは項目直下 + 右サイド一覧 + 送信時サマリーの3段階で案内

---

## 4-5. 進行管理画面

### 目的
- 複数案件や作業工程を俯瞰し、遅延・滞留・偏りを把握する。

### レイアウト
- **上部ヘッダー**
  - 左: タイトル「進行管理」
  - 中央: 期間切替（日 / 週 / 月）
  - 右: 絞り込み、表示形式切替、エクスポート
- **上段サマリー**
  - 進行中件数、完了率、遅延件数、承認待ち件数
- **メインエリア**
  - 表示切替:
    - 工程別ボード（カンバン風）
    - タイムライン表
    - 担当者別進捗表
- **下部固定アクションバー**
  - 「担当再割当」「期限変更」「進捗更新」「一覧へ戻る」

### ワイヤーイメージ
- 標準は工程別の列構成
- 各カードには案件名、期限、担当、警告ラベルを最小要素で表示
- 管理者はドラッグではなく**選択 + 操作**を基本にして誤移動を防ぐ

## 6. 状態設計

各基本画面ごとに、**loading / empty / error / normal** の4状態を定義する。

## 6-1. 一覧画面の状態

### loading
- ヘッダーと表の枠を先に表示
- 表部分は行単位のスケルトンを表示
- 操作可能なボタンは最小限に制限

### empty
- 条件に一致する案件がないことを明示
- 「条件をクリア」「新規作成」の行動を提示
- 初回利用時はガイド文を表示

### error
- 表領域内にエラーバナー表示
- 原因が取得失敗なのか権限不足なのかを分けて表示
- 「再読み込み」「条件を変更」を設置

### normal
- 表またはカード一覧を表示
- 行選択、一括操作、詳細遷移が可能

## 6-2. 詳細画面の状態

### loading
- 上部タイトル、ステータス、カード枠をスケルトン表示
- 下部主要アクションは無効化表示

### empty
- 通常は発生しにくいが、削除済み・参照不可時に使用
- 「一覧へ戻る」を主導線にする

### error
- 案件取得失敗時は画面中央で明示
- 一部情報のみ取得失敗なら該当カード単位でエラー表示

### normal
- 左右カラムに情報表示
- 権限に応じて下部アクションを切替

## 6-3. 入力画面の状態

### loading
- フォーム全体スケルトン
- 入力欄は非活性
- マスタデータ読み込み中を明示

### empty
- 新規入力時の初期状態として扱う
- 未入力でも入力ガイドと例を表示し、空でも不安を与えない

### error
- 保存失敗: 画面上部にバナー、未保存を明示
- バリデーションエラー: 項目下 + エラー要約で表示
- 通信断: オフライン一時保存導線があれば提示

### normal
- 入力可能状態
- 一時保存、確認、送信の導線を明確化

## 6-4. 進行管理画面の状態

### loading
- サマリーカードとボード列をスケルトン表示
- 表示切替ボタンは見せるが無効化

### empty
- 対象期間・条件に該当する案件なし
- 期間変更やフィルタ解除を提案

### error
- サマリー取得失敗と明細取得失敗を分離して表示
- 一部失敗時も他の領域は表示継続

### normal
- 工程別または担当者別に進捗を可視化
- 遅延や滞留をラベルと数値で確認可能

---

## 7. 誤操作防止設計

- 下部固定アクションは最大4件までに絞る
- 危険操作は右端に寄せ、通常操作と余白で分離する
- 「承認」と「差し戻し」は色・ラベル・位置を変える
- 一括処理は複数選択時のみ活性化する
- 送信、完了、削除は対象件名を含む確認ダイアログを出す
- ドラッグ操作は原則採用せず、選択→実行の明示操作に寄せる
- ステータス色だけに頼らず、チップ文言を併記する
- 重要データ変更時は差分確認を表示する

---

## 8. ビジュアル / デザインルール

### 色
- ベースは白・ライトグレー・落ち着いたブルーグレー
- 強調色は1系統に絞る
- エラーは赤、警告はアンバー、成功はグリーンを補助的に使用
- 彩度は抑え、業務画面としての信頼感を優先

### タイポグラフィ
- 見出しは太め、本文は可読性優先
- 数値やステータスは揃えて表示
- 表の文字サイズは詰めすぎず、iPad閲覧時に無理のない密度に調整

### 余白
- セクション間は広め、項目間は狭め
- 情報カード内は8 / 12 / 16 / 24px の段階余白で統一

### 形状
- カード角丸は中程度
- 影は弱く、階層は余白と面で表現
- 装飾線より、背景トーン差でグルーピングする

## 9. 画面遷移

```text
ダッシュボード
 ├─ 案件一覧
 │   ├─ 案件詳細
 │   │   ├─ 入力画面
 │   │   ├─ 履歴画面
 │   │   └─ 承認/差し戻しダイアログ
 │   └─ 検索・絞り込みパネル
 ├─ 進行管理
 │   ├─ 案件詳細
 │   ├─ 担当再割当ダイアログ
 │   └─ 期限変更ダイアログ
 ├─ 通知・履歴画面
 └─ 新規入力画面
```

### 主な遷移ルール
- **ダッシュボード → 一覧**: 件数カードや注意案件カードから遷移
- **一覧 → 詳細**: 行タップまたはカードタップで遷移
- **詳細 → 入力**: 「報告入力」「編集」から遷移
- **入力 → 詳細**: 保存または送信後に戻る
- **進行管理 → 詳細**: カードや行選択で遷移
- **どの画面からも通知へ**: 右上通知アイコン経由で遷移

## 10. 役割別の見せ方

### 現場担当者向け
- 自分に必要な情報を優先表示
- 操作は「開始」「完了」「報告」など実行系中心
- 難しい管理項目は折りたたみまたは非表示

### 管理者向け
- 複数案件の比較・横断把握を重視
- 承認、差し戻し、再割当、期限変更を目立たせる
- 集計、偏り、滞留が一目で分かる表示を強化

### 共通化方針
- 画面レイアウト骨格は共通
- 表示カードの数、右カラム情報、アクションバー内容を役割で切り替える
- 同一端末を共有しても迷わないよう、操作位置は固定する

## 11. 実装時の優先順位

### 優先度A
- 案件一覧
- 案件詳細
- 入力画面
- 下部固定アクションバー
- 状態設計（loading / empty / error / normal）

### 優先度B
- 進行管理画面
- 絞り込みパネル
- 通知 / 履歴画面
- 一括処理導線

### 優先度C
- 表示切替（表 / カード / ボード）
- 補助的なショートカット
- 高度な分析表示

## 12. まとめ

本設計では、iPad業務利用において重要な「一覧性」「誤操作防止」「下部固定アクション」「役割共通UI」を軸に、以下を実現する。

- 一覧、詳細、入力、進行管理の4基本画面で業務を完結できる
- 情報密度は高いが、1画面1目的で迷いにくい
- 現場担当者と管理者の双方が同じ学習コストで利用できる
- loading / empty / error / normal を画面単位で定義し、運用時の不安を減らす
- 高級感よりも、信頼感・整理感・実務性を優先したUIとする
