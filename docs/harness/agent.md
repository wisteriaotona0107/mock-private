# Harness Execution Agent Policy

この `agent.md` は、`docs/harness/*.md` を実行制御するための運用ポリシーです。

## 1. 目的
- 設計ドキュメント（要件〜検証）を、承認ゲートに沿って安全に実行する。
- 先走った実装を防ぎ、レビュー結果を反映してから次工程へ進める。

## 2. 実行対象
- `00_requirements.md`
- `01_architecture.md`
- `02_detail_design.md`
- `03_test_design_and_traceability.md`
- `04_implementation_harness_plan.md`
- `05_user_story_validation.md`

## 3. 実行フェーズ制御
1. 要件レビュー（Gate #1）承認
2. 基本設計レビュー（Gate #2）承認
3. 詳細設計レビュー（Gate #3）承認
4. テスト設計レビュー（Gate #4）承認
5. 製造開始（`04`に従う）
6. ユーザーストーリー検証（`05`に従う）

**ルール:** Gate未承認の次フェーズは実行不可。

## 4. バージョン方針
### v1（初期製造）
- 目的: **機能実現を優先**した最小実装（MVP）を成立させる。
- UI/UXは暫定でよく、まずは「QR + 重量取得 + 確認保存フロー」を完走させる。

### v2（次バージョン以降の生成）
- 生成実行前に、以下の方針が**決定済み**であることを必須とする。
  - 目的とするUI方針（情報密度、操作導線、アクセシビリティ）
  - 対象ペルソナ（例: 倉庫作業者、検品担当、初心者/熟練者）
  - 利用文脈・対象環境（現場照度、片手操作、デバイスサイズ等）
- 上記が確定してから、設計・生成内容を調整して実行制御する。

## 5. 未指定時の扱い（必須）
以下が未指定のまま生成依頼が来た場合は、**実行せず問い直す**。
- UI方針
- ペルソナ
- 利用文脈/向け（誰に・どこで・どう使うか）

### 問い直しテンプレート
> 生成実行前に方針確認が必要です。  
> 1) 想定ペルソナ（誰向け）  
> 2) UI方針（重視する体験）  
> 3) 利用文脈（利用場所・端末・制約）  
> を指定してください。未指定の場合は実行を保留します。

## 6. 実行ログ要件
- 実行時は、フェーズ・承認者・承認日時・対象コミットを記録する。
- v2以降は、UI方針/ペルソナ定義の参照元をログに必ず残す。

## 7. 逸脱時の処理
- Gate未承認で進行要求があった場合は拒否し、必要な承認フェーズを明示する。
- 方針未指定でv2生成要求があった場合は、5章のテンプレートで確認を返す。
