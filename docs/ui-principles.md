# ui-principles

## UI設計原則
- 1画面1目的を徹底し、利用者が次の操作を迷わない構成にする。
- 一覧は比較、詳細は判断、編集は更新という責務分離を明確にする。
- 重要情報は「状態→期限/時刻→担当者」の順で視認できる配置にする。
- iPad横向き利用を基準に、左で選択・右で内容確認できる情報設計を優先する。
- 操作結果は必ず即時フィードバックし、成功・失敗・保留の区別を明示する。
- 用語は業務用語に統一し、同義語の混在を避ける。
- タップ対象は業務利用の連続操作を想定し、誤操作しにくいサイズと間隔を維持する。

## 禁止事項（AIっぽさ排除）
- 意味の薄い汎用スローガンや抽象的キャッチコピーを画面内に置かない。
- 英語ダミーテキスト、無意味なランダム数値、整いすぎたサンプル名を使用しない。
- すべてが「最適」表示になる理想化データを避け、現場で起こる偏りを前提にする。
- 根拠のない自動分析コメントや過剰な提案文を初期表示に含めない。

## 業務UIらしさの定義
- 業務判断に必要な情報が、同一画面で過不足なく確認できる。
- 記録主体（誰が更新したか）と時系列（いつ更新されたか）が追える。
- 状態に応じて優先度が読み取れ、対応要否を即断できる。
- 例外状態（未設定、差戻し、保留）を通常状態と同等に扱い、隠さない。

## 表示要素のルール
- 主要レコードには必ず「最終更新日時」「更新担当者」「現在状態」を表示する。
- 状態は定義済みラベルで表現し、色だけに依存しない（文字ラベル併記）。
- 日時は「YYYY/MM/DD HH:mm」形式で統一し、相対表現のみを避ける。
- 担当者は個人名＋所属の最小単位で表示し、責任範囲を曖昧にしない。
- 空データ時も見出し・項目名は維持し、何が未登録かを明確化する。

## 配色・余白・タイポグラフィ方針
- 配色はニュートラル基調＋状態色の最小構成とし、装飾目的の多色使用を避ける。
- 状態色は「注意」「異常」「完了」など業務判断に必要な意味に限定する。
- 余白は可読性優先で一定リズムを保ち、情報密度の差を意図的に作る。
- 文字は可読性重視の標準ウェイトを基本とし、強調はサイズ差よりウェイト差を優先する。
- 見出し・本文・補足情報の階層を3段階程度に抑え、視線移動を安定させる。
