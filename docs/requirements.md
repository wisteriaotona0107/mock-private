# requirements.md

## 1. 目的
本システムは、小規模事業者向けの商品公開サイトです。管理側 WordPress で定義された商品情報を静的 JSON として反映し、公開側は JSON を読み込んで商品情報を表示します。

## 2. スコープ
### 対象
- 静的HTMLで構成された公開画面
- `data/products.json` の取得
- 商品一覧表示
- 商品詳細表示導線
- 読み込み中表示
- エラー表示
- 商品0件時表示
- 画像欠損時フォールバック
- iPad閲覧を考慮したレスポンシブ対応

### 対象外
- WordPress管理画面
- 商品登録/更新UI
- JSON生成処理
- 画像複製処理
- 本番反映処理
- API認証
- DB設計

## 3. 前提条件
- 公開サイトは静的HTML / CSS / JavaScriptで構成する
- 商品データは `data/products.json` に配置される
- 画像は静的公開側の所定パスに複製済みである
- 公開側はDBに依存しない
- iPadでの閲覧を重視する
- セキュリティを優先する

## 4. 機能要件
### 4.1 商品一覧表示
- `data/products.json` を読み込み、商品一覧を表示する
- 各商品カードに画像、商品名、価格、カテゴリ、説明を表示する
- `visible === true` の商品のみ表示する
- `sortOrder` がある場合は昇順で表示する

### 4.2 商品詳細表示
- `products/index.html?id=<productId>` で商品詳細を表示する
- 一覧へ戻る導線を設ける

### 4.3 状態表示
- JSON取得中はローディングを表示する
- JSON取得失敗時はユーザー向けエラーを表示する
- 表示対象商品が0件の場合は空状態を表示する
- 画像欠損時はフォールバック画像に差し替える

## 5. 非機能要件
### 5.1 セキュリティ
- JSON由来文字列は `textContent` で描画する
- `innerHTML` の多用を避ける
- 管理用URLや秘密情報を埋め込まない
- エラー詳細を画面に表示しない

### 5.2 保守性
- 小規模案件向けに単純な責務分割を行う
- ビルドツールや外部ライブラリに依存しない

### 5.3 ユーザビリティ
- iPad幅(768-1024px)で2〜3カラム表示を維持する
- タップしやすいカードUIを採用する

## 6. 利用環境
- PCブラウザ
- iPad Safari
- スマートフォンブラウザ
- JavaScript有効環境

## 7. 仮定事項
- 商品件数は小〜中規模
- `id` と `name` は実運用で基本入力される
- 詳細画面は複雑な検索機能を持たない

## 8. Assumption / TODO
- 価格通貨は日本円固定(`¥`)とする
- `id` / `name` 欠損データは公開表示から除外する
