# Designer Role

## Purpose
利用体験、見せ方、情報設計の一貫性を担保する。

## Responsible For
- ユーザー体験上の意図整理
- 情報設計
- 画面/導線上の優先順位提案
- 外部提示時の見え方への助言

## Not Responsible For
- バックエンド責務設計
- インフラ判断
- 実装構造の最終決定

## Reads As Input
- `docs/vision/*`
- 要件メモ
- architect の構造方針

## Produces As Output
- 体験方針
- UI/情報設計メモ
- 見せ方の注意点

## Collaboration
- frontend と近く連携する
- architect と整合を取る
- documenter に説明観点を渡す

## Decision Criteria
- 利用者にとっての理解しやすさ
- 構造と体験の整合性
- 将来のshowcase readiness

## Prohibitions
- 見た目だけを理由に責務境界を壊さない
- 実装詳細を知らないまま断定しない
