# agents/context-tablet-ops.md

## Purpose
このファイルは、業務タブレットUIに特有の運用前提と設計ルールを定義する。

## Operational assumptions
- 利用者は業務中に短時間で操作する
- 片手操作や立ち操作がありうる
- 画面を凝視せずに判断することがある
- 操作ミスは業務ミスにつながる可能性がある
- 繰り返し操作が多い
- 手袋や濡れた手などの特殊事情は明示時のみ考慮する

## Tablet-first design rules
- 押下領域を十分に確保する
- 主要アクションは手の届きやすい位置を優先する
- 一画面の情報量を詰め込みすぎない
- 現在地を常に見失わせない
- 戻る、閉じる、保存、確定などの主要操作は一貫配置を心がける
- スクロール依存を強くしすぎない
- モーダル乱用を避ける
- 重要情報は視線移動が少ない位置に置く

## Minimum ergonomic guidelines
- ボタンやタップ対象は十分な高さ・幅を持たせる
- 文字サイズは立ち操作でも判読しやすい水準を優先する
- 細い文字や過剰な情報密度を避ける
- サイドナビやタブは現在地が瞬時に分かること
- 危険操作は主要操作と距離を置く

## Preferred layout patterns
状況に応じて以下を優先的に検討する。
- 左サイドメニュー + 右コンテンツ
- 上部ステータスバー + メイン作業領域
- カードベース一覧 + 右詳細
- タブ切替 + 操作パネル
- フッター固定アクションバー

## State requirements
以下は原則として検討する。
- 通常表示
- 選択中
- 処理中
- 保存完了
- 入力エラー
- データなし
- ネットワーク不調
- 操作不可

## Safety rules
- 削除や確定などの不可逆操作には確認導線を検討する
- 保存未完了状態は見逃させない
- エラー時は原因と次の行動を示す
- 連打事故を防ぐ必要があれば loading / disabled を使う
- 色だけで危険性を示さない

## Workflow alignment
UIは必ず業務フローに沿わせる。
以下を確認すること。
1. 作業開始
2. 対象選択
3. 内容確認
4. 編集または実行
5. 保存または確定
6. 完了確認
7. 次作業への遷移

## Handoff guidance
- 業務フロー不明 → orchestrator に戻す
- 押しやすさ、見やすさの課題 → UI Designer / Reviewer へ
- 状態不足 → State/Data へ
- 実装上の再現課題 → Frontend Impl へ
